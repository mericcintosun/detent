# 05 Information architecture

## Sitemap

```
/                      Operator console
/record/[planHash]     Permanent record of one plan
/how-it-works          How the preview becomes the signing limit
/security              Security model
/faucet                Testnet funding guide
/privacy               Privacy
/terms                 Terms
/design-system         Living style guide, development only, noindex
```

Metadata routes: `sitemap.ts`, `robots.ts`, `manifest.ts`, `opengraph-image.tsx`,
`icon`, `apple-icon`. States: `not-found.tsx`, `error.tsx`, `global-error.tsx`,
loading states that do not change a status code.

## Navigation

| Slot | Items |
| --- | --- |
| Primary | Console, How it works, Security, Faucet |
| Console sections | Register, Plan, Policy, Send, Audit record, rendered as in page navigation on `/` |
| Utility | Theme toggle, command palette (Cmd K), source on GitHub |
| Footer | Privacy, Terms, Security, source, ETHOnline 2026 |
| Mobile | A compact top bar with the mark, the run mode and a menu sheet carrying the primary items and the utility items |

The command palette carries the primary routes, the five console sections,
opening a record by plan hash, toggling the theme, and copying the treasury and
token addresses.

## URL scheme

Lowercase kebab case paths. `planHash` is 0x plus 64 hexadecimal characters,
case insensitive; anything else is a 404 before render. Console state is not
reflected in the URL because a lock is server held and short lived.

## Access

Every page is public and read only. The only write surface is `POST /api/detent`,
rate limited per address and optionally gated by an operator token. The run mode
is visible on every console screen.
